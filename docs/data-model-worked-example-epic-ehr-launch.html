1The EHR-launch OAuth handshake

A clinician opens the app from inside Epic with a patient already in context. This is a genuine sequence — each step feeds the next — ending in an access token scoped to the launched patient. The callback is anonymous, secured by the single-use state and the trusted-issuer check, not a FHIRBridge login.

Epic launches the registered URL

Epic appends the issuer and an opaque launch token to the encrypted, route-scoped launch URL registered on the source.

GET https://app.fhirbridge.io/api/v1/oauth/launch/{ctx} ?iss=https://fhir.epic.com/interconnect-fhir-oauth/api/FHIR/R4 &launch=xY9z-opaque-launch-token

Validate issuer, then redirect to Epic's authorize endpoint

iss must match the source's TrustedIssuers allow-list (anti-phishing). PKCE + state are generated; aud is the FHIR base; the launch token is forwarded.

302 → https://fhir.epic.com/…/oauth2/authorize?response_type=code &client_id=epic-ehr-launch-client-9f2a &redirect_uri=https://app.fhirbridge.io/api/v1/oauth/callback &scope=launch openid fhirUser patient/Patient.read patient/Observation.read patient/Condition.read &launch=xY9z-opaque-launch-token&aud=https://fhir.epic.com/…/R4 &state={enc-nonce}&code_challenge=…&code_challenge_method=S256

Epic redirects back to the callback with an auth code

The user is already signed in to Epic, so no extra prompt. Epic returns the code against the same state.

GET https://app.fhirbridge.io/api/v1/oauth/callback?code=AUTH_CODE&state={enc-nonce}

Exchange the code (confidential client) for a patient-scoped token

The single-use state resolves the pending PKCE verifier; the client secret is pulled from Key Vault at exchange time. Epic returns the token and the launched patient id.

POST /oauth2/token grant_type=authorization_code&code=AUTH_CODE &code_verifier=…&client_id=epic-ehr-launch-client-9f2a&client_secret=•••• ⇒ { "access_token":"…", "patient":"eV3xTk92…", "scope":"patient/…", "expires_in":3600 }

The callback triggers this tenant's route for the launched patient

The route id was carried (encrypted) in the launch context. FHIRBridge extracts Patient + Observation + Condition for that one patient, maps, and writes to SQL — recorded as one ConfiguredPipelineRun.

StartConfiguredPipelineRun { RouteIds:[…0201, …0202, …0203], TriggeredBy:"epic-ehr-launch" }

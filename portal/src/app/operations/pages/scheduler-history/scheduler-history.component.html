Scheduler History

Every time the scheduler recognized due routes and dispatched them for execution.

What am I looking at?

Every row is one moment the scheduler woke up, found due routes, and queued them to run — not the outcome of the run itself. It's written the instant the route is queued, before the pipeline has actually started.

What "Dispatched" does and doesn't mean

It only confirms the scheduler successfully handed the route off to be run. It does not mean the run succeeded — or even that it started. If the queue or a worker process has a problem after this point, the run can be lost with no further trace here.

To see whether a scheduled run actually completed, look up the same Correlation ID in Pipeline Executions. A "Route(s)" value showing a raw ID instead of a name means that route has no resolvable label — a configuration gap worth fixing, not an error.

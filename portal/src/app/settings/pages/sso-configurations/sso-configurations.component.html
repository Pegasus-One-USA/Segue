SAML 2.0 SSO

Lets staff sign in via your organization's own identity provider (Okta, ADFS, Azure AD as a SAML app, etc.).

Give these two URLs to your IdP admin when setting up the trust relationship:

Microsoft Entra ID

"Continue with Microsoft" login. Applies to sign-in only — a separate, legacy path that accepts a raw Entra token directly as an API request still needs a restart to pick up changes, if it's ever used.

Ping Identity (PingOne)

"Continue with Ping" login. Roles are fetched live from PingOne at every sign-in and mapped to Segue roles below, so PingOne stays the source of truth for access.

Group to role mapping

Enter a PingOne Group ID (or exact group name) and pick the one Segue role it grants. A user holds a single role. The order matters when "Use mapping order" is selected below: the top row has the highest priority.

When a user's Ping groups map to more than one role

Groups that are not in the list are ignored. A user in one mapped group, or in several groups that all map to the same role, is never affected by this.

When none of a user's Ping groups are mapped to a role

Applies to users who already have a Segue account; their role is left unchanged. A person with no Segue account and no mapped group is still refused.

When the Ping role and the user's Segue role differ

The user's record is updated to the Ping-mapped role, with a note "Role updated via PingOne SSO" and an entry in the authentication log.

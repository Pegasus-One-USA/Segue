Security Events

Lockouts, threshold breaches, and other security-relevant events outside normal auth/config flows.

What am I looking at?

Every row is a notable security event — an account getting locked out after too many failed logins, an admin regenerating an application secret, or the system detecting the audit trail itself may have been tampered with. These are rarer and generally more serious than routine authentication activity.

Severity

Critical (e.g. audit chain broken) needs immediate attention. High (e.g. account locked, secret regenerated) is worth reviewing. Medium (e.g. a login attempt on an already-locked account) is informational.

This is also the only data source the Alert Rules engine watches — if you want an email when something like a lockout threshold is hit, build the rule against this event data.

Alert Rules

Real, evaluated conditions — count of a SecurityEvent type within a time window exceeding a threshold. Evaluated every few minutes; firing sends a real email and records the alert.

What am I looking at?

Each rule you create here is a real, running condition: "if event type X happens more than N times within Y minutes, email these recipients." A background job genuinely checks every enabled rule on a schedule — this isn't a mockup.

Rules can only watch Security Events today — not Errors, Pipeline Executions, or any other log type.

Event types — what each one actually means

Event type Meaning
Login attempt while locked Someone tried to log in to an account that's already locked out from too many prior failed attempts.
Account locked (threshold reached) A user account just got locked out because it hit the failed-login limit — the lockout is happening right now, not just being attempted against.
App secret regenerated An internal signing secret (e.g. the key that signs login tokens or password-reset links) was replaced — anything signed with the old value stops working immediately.
Audit chain broken The tamper-evident audit log's hash chain no longer verifies — a critical signal that audit history may have been altered outside the application (e.g. a direct database edit).

Trigger a FHIRBridge workflow and receive the data at your API

You add one small piece of code to your system. When it runs, FHIRBridge fetches the data from the EHR (Epic, athenahealth or eCW) and sends it to your API. This page says what we give you, what we need from you, and the code to copy. Section 2 shows how it matches the Seque integration document you already wrote (ChartChat).  Version 3.1

1The idea in one minute

  1. Your PHP code asks FHIRBridge to start the workflow (one web request, with the details we gave you).
  2. FHIRBridge runs the workflow: it reads the data from the EHR and prepares it.
  3. FHIRBridge sends the data to your API as normal web requests (HTTP POST with JSON). This is what you will see on your side.
You do not receive the data in the trigger call.The trigger only starts the work. The data arrives afterwards, at your API, from FHIRBridge.

Your Seque-start endpoint becomes this

Today it returns Seque-connect-url?state=token. Now it asks FHIRBridge for the one-time link instead. Everything else in your flow (the patient is logged in, the token is stored for two hours, the browser is redirected to authorizeUrl) stays the same. Your stack is TypeScript, so here is that endpoint in TypeScript; the PHP version is in section 5.

routes.ts (Seque-start)
// POST /fhir/ehr-import/Seque-start   (patient is logged in)
const state = await createBrokerToken({ internalPatientId });      // your existing 2-hour token

const response = await fetch(`${process.env.FHIRBRIDGE_BASE_URL}/api/v1/workflows/external/launch-ticket`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    client_id: process.env.FHIRBRIDGE_CLIENT_ID,
    client_secret: process.env.FHIRBRIDGE_CLIENT_SECRET,     // server only
    workflow_id: process.env.FHIRBRIDGE_WORKFLOW_ID,
    ehr_endpoint_code: process.env.FHIRBRIDGE_EHR_CODE,
    return_url: 'https://ccdemo.pegasusone.com',              // the Member Portal address you gave us
    state,                                                     // comes back to you as "token" on every push
    mode: 'async',
    window_mode: 'same',
  }),
});
if (!response.ok) throw new Error(`FHIRBridge refused: ${response.status}`);

const { run_url } = await response.json();
return { authorizeUrl: run_url };                              // the browser is redirected here

5What you build (PHP)

You need PHP 7.4 or newer with the cURL extension. You write the small files below; there is nothing to install.

Which case are you? Case A – a person is involved (a patient or clinician signs in to their EHR account on a screen): your page sends the person to FHIRBridge for the sign-in, then they come back.
Case B – no person (your server just triggers the data transfer, for example from a button, a cron job or a back-office page): one call from your server, nothing is shown to anyone.
We tell you which one applies to your workflow. The first two files are the same for both.

Step 1 – the configuration file

Store it outside your public web folder. Do not commit the secret to version control.

config.php
<?php
// config.php  -  values we gave you

    'base_url'      => 'https://YOUR-PORTAL-BASE-URL',            // Portal Base URL (no trailing slash)

    'return_url'    => 'https://app.yourcompany.com/fhirbridge-return.php',
];

Step 2 – a small helper that calls FHIRBridge

fhirbridge.php
<?php
// fhirbridge.php  -  sends a JSON request and returns status, headers and body

function fb_request(string $method, string $url, ?array $payload = null): array
{
    $ch = curl_init($url);
    curl_setopt_array($ch, [
        CURLOPT_CUSTOMREQUEST  => $method,
        CURLOPT_HTTPHEADER     => ['Content-Type: application/json', 'Accept: application/json'],
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_HEADER         => true,
        CURLOPT_FOLLOWLOCATION => false,   // we want to read redirects ourselves
        CURLOPT_TIMEOUT        => 30,
    ]);
    if ($payload !== null) {
        curl_setopt($ch, CURLOPT_POSTFIELDS, json_encode($payload));
    }

    $raw = curl_exec($ch);
    if ($raw === false) {
        $error = curl_error($ch);
        curl_close($ch);
        throw new RuntimeException('Could not reach FHIRBridge: ' . $error);
    }

    $status     = curl_getinfo($ch, CURLINFO_RESPONSE_CODE);
    $headerSize = curl_getinfo($ch, CURLINFO_HEADER_SIZE);
    curl_close($ch);

    $headers = substr($raw, 0, $headerSize);
    $body    = substr($raw, $headerSize);

    return ['status' => $status, 'headers' => $headers, 'body' => $body, 'json' => json_decode($body, true)];
}

Case A – a person signs in

A1. A page of yours that starts it. Protect it with your own login. It asks FHIRBridge for a one-time link and sends the browser there.

start.php
<?php
// start.php  -  call this from your "Get my records" button (after your own login check)
$cfg = require __DIR__ . '/../config.php';          // adjust the path
require __DIR__ . '/fhirbridge.php';

$res = fb_request('POST', $cfg['base_url'] . '/api/v1/workflows/external/launch-ticket', [
    'client_id'         => $cfg['client_id'],
    'client_secret'     => $cfg['client_secret'],
    'workflow_id'       => $cfg['workflow_id'],
    'ehr_endpoint_code' => $cfg['ehr_code'],
    'return_url'        => $cfg['return_url'],
    'mode'              => 'async',      // "Workflow started" straight away
    'window_mode'       => 'same',       // open in this window
]);

if ($res['status'] !== 200 || empty($res['json']['run_url'])) {
    error_log('FHIRBridge refused: ' . $res['status'] . ' ' . $res['body']);   // see section 8
    http_response_code(502);
    exit('Sorry, we could not start the connection. Please try again later.');
}

// The link works once and for about 90 seconds, so send the browser there right away.
header('Location: ' . $res['json']['run_url']);
exit;

A2. The page the person comes back to (the return_url you gave us).

fhirbridge-return.php
<?php
// fhirbridge-return.php  -  FHIRBridge sends the browser back here when it is done
$status = $_GET['status'] ?? '';
$runId  = $_GET['workflowRunId'] ?? '';
if (!preg_match('/^[0-9a-f-]{36}$/i', $runId)) { $runId = ''; }     // only accept a real id

if ($status === 'Triggered' || $status === 'Succeeded') {
    echo 'Thank you. Your records are being sent. Reference: ' . htmlspecialchars($runId);
} else {
    echo 'The connection could not be completed. Please try again.';
}

Only the first page needs your login. The person sees FHIRBridge's page while they sign in to the hospital; you build no sign-in screens.

Case B – no person involved

One server-side call. Nothing is shown to anyone, so you can run it from a button, a back-office page or a scheduled job.

trigger.php
<?php
// trigger.php  -  starts the workflow from your server, no browser involved
$cfg = require __DIR__ . '/../config.php';
require __DIR__ . '/fhirbridge.php';

$res = fb_request('POST', $cfg['base_url'] . '/api/v1/workflows/external/run', [
    'client_id'         => $cfg['client_id'],
    'client_secret'     => $cfg['client_secret'],
    'workflow_id'       => $cfg['workflow_id'],
    'ehr_endpoint_code' => $cfg['ehr_code'],
    'return_url'        => $cfg['return_url'],   // must be one of the addresses you gave us
    'mode'              => 'async',              // start it and return at once
]);

// A good answer is a redirect (HTTP 302) whose address ends with ?status=Triggered&workflowRunId=...
if ($res['status'] === 302 && preg_match('/^Location:\s*(\S+)/mi', $res['headers'], $m)) {
    parse_str((string) parse_url($m[1], PHP_URL_QUERY), $q);
    if (($q['status'] ?? '') === 'Triggered') {
        echo 'Started. Run reference: ' . ($q['workflowRunId'] ?? '');
        exit;
    }
    error_log('FHIRBridge run failed: ' . ($q['error'] ?? $q['status'] ?? 'unknown'));
    exit('The workflow could not be started.');
}

error_log('FHIRBridge refused: ' . $res['status'] . ' ' . $res['body']);   // see section 8
exit('The workflow could not be started.');

Optional – ask whether a run has finished

Use the run reference. No password is needed.

status.php
<?php
$cfg = require __DIR__ . '/../config.php';
require __DIR__ . '/fhirbridge.php';

$runId = $_GET['run'] ?? '';
if (!preg_match('/^[0-9a-f-]{36}$/i', $runId)) { http_response_code(400); exit; }

$res = fb_request('GET', $cfg['base_url'] . '/api/v1/workflows/external/run-status/' . $runId);
// {"status":"Running"}  or  {"status":"Succeeded"}  or  {"status":"Failed","errorMessage":"... Reference ID: ERR-..."}
header('Content-Type: application/json');
echo $res['body'];

Status values: Running, Succeeded, PartialSuccess, Failed, Cancelled.

7How you know it worked

1. Your trigger code says "Triggered"

Case A: your return page receives ?status=Triggered&workflowRunId=.... Case B: trigger.php prints "Started". Triggered means the work has started, not that it has finished.

2. Your API receives requests from FHIRBridge

After the workflow has read the data, FHIRBridge calls the API URL you gave us. A successful run shows up on your side as one or more normal web requests:

You will seeDetails
Method and addressPOST to the API URL you gave us.
BodyJSON, by default an array of records: [ {...}, {...} ]. Up to 500 records or about 4 MB per request; bigger runs arrive as several requests. The field names are the ones we agreed.
HeadersContent-Type: application/json, your authentication header, and X-Idempotency-Key (a unique id per request).
What we expect backAn HTTP 200–299 answer within 30 seconds.
If your API failsWe retry up to 3 times with a short pause. Because of retries, the same request can arrive twice. Use X-Idempotency-Key to ignore a request you already processed.

A minimal receiving endpoint, as a starting point (adjust the authentication to what we agreed):

receive.php (your API)
<?php
// receive.php  -  the endpoint FHIRBridge pushes the data to
$expected = 'Bearer ' . getenv('FHIRBRIDGE_PUSH_TOKEN');           // the token we agreed
if (!hash_equals($expected, $_SERVER['HTTP_AUTHORIZATION'] ?? '')) {
    http_response_code(401);
    exit;
}

$records = json_decode(file_get_contents('php://input'), true);
if (!is_array($records)) {
    http_response_code(400);
    exit;
}

$key = $_SERVER['HTTP_X_IDEMPOTENCY_KEY'] ?? '';
// if you already stored this $key, answer 200 and do nothing (it was a retry)

foreach ($records as $record) {
    // save $record to your database
}

header('Content-Type: application/json');
echo json_encode(['received' => count($records)]);               // HTTP 200
Allow large requestsMake sure your server accepts bodies of at least 8 MB (post_max_size in php.ini, and the limit of your web server or gateway), otherwise large batches are refused.

3. Optional – ask FHIRBridge

status.php (above) shows Succeeded when the whole run, including the delivery to your API, has finished. If it shows Failed, send us the Reference ID from the message.

9Go-live checklist

We do us

  • Set up the EHR connection (Epic / athenahealth / eCW).
  • Add the hospital / practice and give you its EHR Code.
  • Build the workflow and its API destination that points to your API, with your authentication.
  • Create your Client ID and Secret.
  • Allow-list your website address(es).
  • Send you the five values (section 3), the Epic client id and redirect address, and tell you Case A or B.

You do you

  • Send us your website address(es), your API URL, its authentication and the expected data (section 4).
  • Allow requests from FHIRBridge to reach your API.
  • Add the PHP files above and put the five values in config.php.
  • Make your API answer 200 and handle repeated requests.
  • Run one test together with a test patient: start from your Seque-start, sign in to MyChart, see Triggered, then see the requests arrive at your seque-ingest with your token in each one.
Keep the Client Secret on your serverNever put it in a web page, JavaScript, a mobile app, a URL or a log. If it may have leaked, tell us and we will issue a new one; the old one stops working at once.
